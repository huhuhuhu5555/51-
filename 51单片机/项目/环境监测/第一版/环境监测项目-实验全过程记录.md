## 二、阶段一：DS18B20 温度采集 + 串口上报（已完成）

### 2.1 硬件接线

| DS18B20 | 接到 |
|---|---|
| VCC | 3.3V / 5V |
| GND | GND |
| **DQ（数据）** | **P3.7** |

### 2.2 单总线协议要点

| 时序项 | 要求 |
|---|---|
| 复位脉冲 | 主机拉低 ≥480µs（实际用 750µs） |
| 存在脉冲（应答） | 器件在 15~60µs 内拉低，持续 60~240µs |
| 写 1 | 拉低 1~15µs 后释放 |
| 写 0 | 拉低 ≥60µs |
| 读位 | 主机拉低 ≥1µs，15µs 内采样 |
| **位顺序** | **LSB first（低位先发）** |
| ROM 命令 | `0xCC` 跳过 ROM |
| 功能命令 | `0x44` 启动转换 / `0xBE` 读暂存器 |
| 转换时间 | 最长 750ms（12 位精度） |

### 2.3 完整代码（跑通版本）

```c
#include "reg52.h"
#include "intrins.h"
typedef unsigned char u8;
typedef unsigned int u16;

u8 dat = 0;
sbit DQ = P3^7;                     // 温度传感器端口

void delay_ten_us(u16 us)           // 延时函数（参数必须 u16）
{
    while(us--);
}

void delay_ten_ms(u16 ms)
{
    while(ms--)
    {
        delay_ten_us(100);          // 约 1ms
    }
}

void uart_send(u8 dat)              // 串口发送
{
    TI = 0;
    SBUF = dat;
    while(!TI);
    TI = 0;
}

u8 ds_check(void)                   // 复位 + 检测应答，返回 1=检测到
{
    u8 wait = 0;

    DQ = 1;
    delay_ten_us(1);
    DQ = 0;
    delay_ten_us(75);               // 拉低约 750us
    DQ = 1;

    wait = 0;
    while(DQ && wait < 200)         // 第一步：等 DQ 变低（应答开始）
    {
        wait ++;
        delay_ten_us(1);
    }
    if(DQ == 1) return 0;

    wait = 0;
    while((!DQ) && wait < 200)      // 第二步：再等 DQ 变高（应答结束）
    {
        wait ++;
        delay_ten_us(1);
    }
    return 1;
}

u8 ReadByte(void)                   // 读一个字节（LSB first）
{
    u8 i;
    for (i = 0; i < 8; i++)
    {
        dat >>= 1;
        DQ = 0;
        _nop_(); _nop_();           // 延时 2us
        DQ = 1;
        _nop_(); _nop_(); _nop_(); _nop_();   // 延时 4us
        if(DQ == 1)
        {
            dat |= 0x80;            // 新位放最高位，右移后被挤到 bit0
        }
        delay_ten_us(5);
    }
    return dat;
}

void WriteByte(u8 dat)              // 写一个字节
{
    u8 i;
    for (i = 0; i < 8; i++)
    {
        DQ = 0;
        if(dat & 0x01)              // 写 1
        {
            _nop_(); _nop_();
            DQ = 1;
            delay_ten_us(6);
        }
        else                        // 写 0
        {
            delay_ten_us(6);
            DQ = 1;
            _nop_(); _nop_();
        }
        dat >>= 1;
    }
}

u8 ds_read_temp(void)               // 读温度，返回整数摄氏度
{
    u8 low;
    u8 high;
    u16 raw;

    ds_check();
    WriteByte(0xCC);                // 跳过 ROM
    WriteByte(0x44);                // 启动转换
    delay_ten_ms(800);              // 等转换完成

    ds_check();
    WriteByte(0xCC);
    WriteByte(0xBE);                // 读暂存器
    low  = ReadByte();
    high = ReadByte();

    raw = high;
    raw = raw << 8;
    raw = raw | low;

    return raw >> 4;                // 12 位数据右移 4 位得整数温度
}

void main()
{
    u8 t;

    TMOD = 0x20;                    // 定时器1 方式2（波特率发生器）
    TR1 = 1;
    TH1 = 0xFD;                     // 9600bps @11.0592MHz
    TL1 = 0xFD;
    PCON &= 0x7F;                   // 波特率不倍增
    SCON = 0x50;                    // 串口方式1，允许接收

    delay_ten_ms(100);
    while(1)
    {
        t = ds_read_temp();

        uart_send(t / 10 + '0');    // 十位
        uart_send(t % 10 + '0');    // 个位
        uart_send('\n');

        delay_ten_ms(1000);
    }
}
```

### 2.4 踩过的坑

| 编号 | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | 一直显示 **15℃** | 延时函数参数用了 `u8`，循环速度快一倍，整个单总线时序被压缩 | 参数改成 `u16` |
| 2 | 一直显示 **15℃** | 复位后只等 DQ「变低」就返回，应答还没结束就急着写命令 → 命令丢失 | 再等 DQ「变高」，让应答结束 |
| 3 | 显示 **85℃** | 转换没等够时间 | 延时加到 ≥750ms |

**关键认识**：

- **85℃** = DS18B20 上电默认值，读到它说明**转换根本没执行**
- **15℃** = **时序整个错位**（延时不准）

### 2.5 验收

串口 9600，每 1 秒输出一次整数温度，**实测通过**。

## 三、阶段二：LCD9648 图形点阵屏（驱动完成，屏未点亮，搁置）

### 3.1 屏幕信息

| 项目 | 值 |
|---|---|
| 分辨率 | 96×48 图形点阵 |
| 驱动 IC | **UC1701** |
| 接口 | 8 脚：`GND VCC NC SCL SDA RS CS RST` |
| 通信方式 | **S8 四线串口（只写，不能读）** |

### 3.2 接线

| 屏脚 | 接到 |
|---|---|
| GND | GND |
| VCC | 5V |
| NC | 空 |
| **SCL** | **P0.6** |
| **SDA** | **P0.5** |
| **RS** | **P0.4** |
| **CS** | **P0.3** |
| **RST** | **P0.2** |

插在板上 16 针的 LCD1602 接口（普中官方教程载明该口兼容 LCD9648）。

### 3.3 S8 串口时序

| 项目 | 要求 |
|---|---|
| **位顺序** | **MSB first（高位先发，与 DS18B20 相反）** |
| 锁存边沿 | **SCL 上升沿** |
| 片选 | CS 每个字节包一次 |
| 延时 | **不需要**（芯片要求脉宽 ≥15ns，而 51 一条指令就是 1µs） |

### 3.4 驱动开发六步（进度）

| 步骤 | 内容 | 状态 |
|---|---|---|
| 1 | 写字节 + 写命令 + 写数据 | **完成** |
| 2 | 初始化（9 条命令） | **完成** |
| 3 | 清屏 | 未做 |
| 4 | 画点 | 未做 |
| 5 | 画字符 | 未做 |
| 6 | 接温度 | 未做 |

**初始化命令序列**：

```
E2(软件复位) → C8(COM方向) → A0(SEG方向) → 2F(开电荷泵/稳压/跟随)
→ 26(对比度粗调) → 81+10(对比度细调，两条) → AF(开显示) → 40(起始行0)
```

**核心代码（写字节 + 初始化）**：

```c
void lcd9648_spi_write_byte(u8 dat)
{
    u8 i;
    for(i = 0; i < 8; i++)          // 8 位，高位先发
    {
        if((dat & 0x80) != 0)       // 取最高位（注意是 != 0，不是 == 1）
            SDA = 1;
        else
            SDA = 0;

        dat <<= 1;                  // 左移，让下一位来到最高位
        SCL = 0;
        SCL = 1;                    // 上升沿，屏在这一刻读走该位
    }
}

void lcd9648_write_cmd(u8 cmd)      // 写命令
{
    CS = 0;
    RS = 0;
    lcd9648_spi_write_byte(cmd);
    CS = 1;
}

void lcd9648_init(void)             // 初始化
{
    RST = 1; delay_ms(10);
    RST = 0; delay_ms(10);
    RST = 1; delay_ms(10);

    lcd9648_write_cmd(0xE2);
    lcd9648_write_cmd(0xC8);
    lcd9648_write_cmd(0xA0);
    lcd9648_write_cmd(0x2F);
    lcd9648_write_cmd(0x26);
    lcd9648_write_cmd(0x81);
    lcd9648_write_cmd(0x10);
    lcd9648_write_cmd(0xAF);
    lcd9648_write_cmd(0x40);
}
```

### 3.5 硬件排查记录（按五层法）

| 层次 | 测了什么 | 结果 |
|---|---|---|
| ① 电源 | 屏 VCC–GND 电压 | **≈5V，正常** |
| ② 连接 | 引脚对应关系 | **一一对应** |
| ③ 信号 | SDA 波形 | **有波形** |
| ③ 信号 | SCL 波形 | 起初抓不到 → 后实测 **52.982 kHz**，完全符合 51 软件 SPI 速度，**正常** |
| ③ 信号 | RST 复位脉冲 | 示波器抓到 **10ms 低脉冲**，**正常** |
| ④ 协议 | 时序 | 代码与官方逐行一致，**排除** |
| ⑤ 器件 | 屏本身 | **未做交叉验证（没有第二块同型号屏）** |

**旁证**：LCD1602A 插同一个 16 针口**能正常点亮** → 板子、P0 口、上拉排阻全部正常。

### 3.6 结论

**软件侧全部排除，硬件侧只剩"屏本身"未验证。最大嫌疑是屏损坏。** 代码保留，日后换屏再试。

## 四、阶段三：改用 LCD1602A（进行中）

### 4.1 决策原因

- 1602A **已实测能点亮**，硬件通路已验证
- 字符屏驱动比图形屏**简单得多**
- 显示温度这个场景，1602A 完全够用
- 9648 驱动代码**保留**，以后换屏再战

### 4.2 引脚定义

```c
sbit LCD1602_RS = P2^6;         // 数据/命令选择
sbit LCD1602_RW = P2^5;         // 读写选择
sbit LCD1602_E  = P2^7;         // 使能
#define LCD1602_DATAPORT P0     // 8 位数据口 = P0 整口
```

插同一个 **16 针接口**，位置不用动。

### 4.3 驱动开发六步

| 步骤 | 内容 |
|---|---|
| 1 | 写命令 / 写数据（并口时序：E 下降沿锁存） |
| 2 | 初始化（4 条命令） |
| 3 | 清屏 |
| 4 | 显示一个字符 |
| 5 | 显示字符串 |
| 6 | 接入温度 |

**与 LCD9648 的关键区别**：

| 项目 | LCD9648 | LCD1602A |
|---|---|---|
| 接口 | **串行**（一位一位发） | **并行**（8 位一起送） |
| 数据线 | SCL + SDA 两根 | **P0 八根** |
| 锁存边沿 | SCL **上升沿** | E **下降沿** |
| 控制线 | RS / CS / RST | RS / RW / E |
| 显示内容 | 任意图形、汉字 | 字符（字母数字符号） |

## 五、经验与教训

1. **延时函数的参数类型能毁掉整个时序** —— `u8` 让循环快一倍，DS18B20 直接恒 15℃
2. **协议要看"结束条件"** —— 应答不只要"变低"，还得等它"变高"
3. **位序必须对照手册** —— DS18B20 是 LSB first，UC1701 是 MSB first，反了就是乱码
4. **改代码前先确认文件编码** —— GBK / UTF-8 混用会让中文注释乱码
5. **复制文件要复制"文件本身"** —— 在编辑器里复制粘贴文字，会把乱码一起带过去
6. **硬件排查要分层** —— 电源 → 连接 → 信号 → 协议 → 器件；下层没确认，上层结论都不可信
7. **一次只改一个变量** —— 同时改多处，就不知道是哪一处起的作用
8. **善用"已知好的"做参照** —— 官方 hex、另一块屏、另一个引脚，能把范围快速二分
9. **仪器要摸清能力边界** —— 200kHz 带宽的示波器抓不了 1µs 的脉冲，别在窄脉冲上浪费时间
