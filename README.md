# 51 单片机学习 —— 串口通信与按键输入

STC89C52（11.0592MHz）上的串口收发与独立按键练习，全部代码手写，未照抄教程。

## 功能

按一次独立按键，计数加一，通过串口以 **9600 波特率**发送到电脑串口助手显示，一行一个数字。

```
1
2
3
...
10
11
```

## 硬件连接

| 功能 | 单片机引脚 | 对端 | 说明 |
|---|---|---|---|
| 独立按键 | P3.2 | GND | 不按下 = 高（内部弱上拉），按下 = 低 |
| 串口发送 | P3.1 (TXD) | USB 转串口模块的 RXD | **必须交叉** |
| 串口接收 | P3.0 (RXD) | USB 转串口模块的 TXD | **必须交叉** |
| 晶振 | — | 11.0592MHz | 保证 9600 波特率整除，精确无误差 |

## 关键实现

**串口初始化**（11.0592MHz / 9600 / SMOD=0）

```c
TMOD = 0x20;      // T1 方式 2（8 位自动重装），溢出率稳定
TH1  = 0xFD;      // 256 - 11059200/(384*9600) = 253
TL1  = 0xFD;
SCON = 0x50;      // 方式 1（8 位 UART）+ REN 允许接收
PCON &= 0x7F;     // SMOD = 0，波特率不加倍
TR1  = 1;         // 启动波特率发生器（最容易漏的一步）
```

波特率公式：`波特率 = fosc / (384 × (256 − TH1))`

**按键消抖**：延时约 45ms → 二次确认仍是按下 → 计数 → 等松手（`while(KEY==0)`）

**数字转字符发送**：
- 单个数字：`count + '0'`（即 +48，把 0~9 映射到 ASCII 的 48~57）
- 两位数：`count/10 + '0'` 发十位，`count%10 + '0'` 发个位
- 换行：`'\n'`（ASCII 10），直接发，不需要再转换

## 踩过的坑（真金白银换来的）

1. **`while(1);` 后面的代码永远不会执行** —— 延时写在了循环外面，程序只跑没有延时的版本，串口疯狂刷屏。

2. **`SBUF = count` 发出去的不是字符** —— 发的是原始数值。count=1 时发出的是 ASCII 1（SOH 控制字符，屏幕上不可见）；count=10 时发出的是换行符。正确做法是 `+ '0'`。

3. **count 超过 9 会"跑出数字区"** —— `count + '0'` 只能把 0~9 映射到 `'0'~'9'`。count=10 时 48+10=58，那是冒号 `:` 的编码；count=17 时 48+17=65，那是大写 `A`。实测现象就是 `123456789:;<=>?@ABC...`，等于把 ASCII 码表打出来了。

4. **串口助手的 HEX 模式会误导** —— 它把收到的字节按两位十六进制显示（收到字符 '1' 显示 `31`，收到数值 1 显示 `01`）。调试时要清楚自己看的是哪种模式。

5. **函数定义和调用的写法不同** —— 定义要写类型和参数名 `void uart_send(u8 dat)`；调用只写值 `uart_send('A')`，不能写成 `uart_send(u8 A)`。

6. **`'\n'` 本身就是字符** —— 不需要再 `+ '0'`。判断法则：算出来的**数字**要转换，写好的**字符**直接用。
